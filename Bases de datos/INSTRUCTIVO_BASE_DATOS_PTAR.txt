1. ARQUITECTURA GENERAL
================================================================================

La BD tiene 3 capas:

  CAPA 1 — CATÁLOGOS (datos fijos de referencia)
  CAPA 2 — TABLAS DE HECHOS (registros operativos con fecha y turno)
  CAPA 3 — VISTAS (cálculos automáticos que unen las tablas)

Los formularios de la app escriben en CAPA 2.
Los gráficos del dashboard leen de CAPA 3 (vistas) o CAPA 2 directamente.

================================================================================
2. CATÁLOGOS (CAPA 1)
================================================================================

TABLA               REGISTROS  DESCRIPCION
parametro_calidad      21       Lista de 21 parámetros: Temperatura, pH, DQO, TDS, SST...
unidad_tratamiento     15       Unidades del tren: Tanque Pulmon, GEM Salida, MBR1...
producto_quimico       16       Químicos GEM y RO con precio y densidad
ptar_users              3       Usuarios del sistema con roles (operario/encargado/admin)

NOMENCLATURA DE TURNOS:
  turno 1 = Noche    (10pm - 6am)
  turno 2 = Mañana   (6am  - 2pm)
  turno 3 = Tarde    (2pm  - 10pm)

7. CÓMO SUBIR LA BD A OTRO SERVIDOR
================================================================================

PASO 1 — En el servidor ORIGEN (este equipo), ejecutar el dump:
  mysqldump -h 127.0.0.1 -u root -p ptar_permoda > ptar_permoda_dump.sql

PASO 2 — En el servidor DESTINO, crear la base de datos:
  mysql -h [HOST_DESTINO] -u [USUARIO] -p -e "CREATE DATABASE ptar_permoda CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

PASO 3 — Importar el dump:
  mysql -h [HOST_DESTINO] -u [USUARIO] -p ptar_permoda < ptar_permoda_dump.sql

PASO 4 — Verificar:
  mysql -h [HOST_DESTINO] -u [USUARIO] -p ptar_permoda -e "
    SELECT TABLE_NAME, TABLE_ROWS FROM information_schema.TABLES
    WHERE TABLE_SCHEMA='ptar_permoda' AND TABLE_TYPE='BASE TABLE'
    ORDER BY TABLE_NAME;"
